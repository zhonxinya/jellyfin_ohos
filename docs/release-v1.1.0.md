# Jellyfin 鸿蒙客户端 v1.1.0

自 v1.0.0 以来的第一个功能版本：**设置与管理端整体重做**，播放侧补上
**短视频模式 / 画中画 / 硬解失败无感切软解**，并修掉若干"看起来能改、其实没保存"的老毛病。

连接你**自行部署**的 Jellyfin 服务器。本应用不包含、不提供任何媒体内容，也不内置任何服务器地址。

## 本版新增

### 播放与「视频」页

- **短视频模式**：在设置里勾选媒体库后，底部「视频」页从这些库里随机抽取影片 / 剧集 / 视频，
  竖屏满屏连播、上下滑动切换（媒体库选择在「设置 → 播放 → 短视频模式」）；
- **页内自动连播**：滑到哪条播哪条，播完自动下一条；
- **默认全屏沉浸式**，支持横屏观看（并修掉竖屏比例不对的问题）；
- **画中画**：系统 PiP 小窗，退到桌面或切应用后继续看；
- **硬解失败无感切换软解**：不再闪一下错误页，播放位置续接；「视频」页里支持就地软解续播
  （硬解不支持的条目不再被跳过）；
- 播放控制面板的非功能区域可撤离；锁定改为「单击显示锁、点锁才解锁」，避免误触；
- 软解提速：用满多核 + `FAST_BILINEAR` 缩放 + 拉帧自调度 + 纹理复用；
- 移除调试 UI（详情页的「软解首帧预览」入口）。

### 设置与管理端（本版重做的主要部分）

- **媒体库管理**按服务端语义重做：列表（封面、路径数、扫描进度）、新建、重命名、删除、
  路径增删改（含网络路径映射）、媒体库选项、扫描；封面支持**从 URL 设置**（由服务器抓取）与删除；
- 新增/重做的设置页：
  - **媒体库显示**（服务器级：显示方式、图片落盘约定、扫描并发、监控延迟）；
  - **媒体库元数据**：13 种条目类型的元数据/图片抓取器开关与顺序（服务器默认值）；
  - **NFO 设置**、**继续观看**、**品牌**；
  - **网络**（34 个字段里做了 23 个：远程访问/端口/HTTPS/证书/Base URL/局域网与代理…）；
  - **转码**（37 个字段里做了 36 个：硬件加速、编码质量、限速、HDR→SDR、隔行扫描、路径与字体…）；
  - **播放（服务器）**：远程码率上限等；
  - **插件仓库**：可添加/删除/启用第三方仓库（以前只能从已配好的仓库装插件）；
  - **常规设置**从 6 个字段扩到 14 个；
- 控制台页面：**活动**（类型图标 + 中文标签 + 本地时间 + 加载更多）、
  **系统信息**（按服务器/运行时/目录分组、中文标签、布尔显示是/否）、
  **本地媒体文件夹**（名称 + 路径 + 类型标签）、
  **日志**（可以看内容：只取结尾 256 KB，避免把十几 MB 的日志整份读进内存）；
- 设置主页与管理入口按「内容管理 / 服务器设置 / 运行状态」分组，行首补上图标；
- 删掉三页**"改了没效果"**的页面：它们写的字段名在 Jellyfin 10.8 里根本不存在
  （`EnableRemoteControl` / `PublicHttpPort` / `InternalHttpPort` / `InternalHttpsPort` / `AllowAv1Encoding`），
  服务端会静默忽略未知字段，所以旧版界面上这些开关点了等于没点。

## 本版修复

- **账号偏好（首页 / 音频 / 字幕 / 显示相关的开关）以前一直没保存成功**：
  端点写错（`POST /Users/Configuration?userId=…` → 正确的是 `POST /Users/{userId}/Configuration`，
  旧写法服务端直接 400），而且部分提交会把其余 13 个字段重置 —— 现在改为
  「读取当前配置 → 合并改动 → 整份提交」；
- **设置主页三个开关点了没反应**：`@Builder` 的按值参数不随状态刷新，点击回调拿到的是**旧值**，
  于是又把旧值写回服务器；
- **设置主页里"算出来"的行会冻住**：主题/短视频模式那几行的副标题停在第一次渲染的值
  （主题页选「浅色」返回后仍显示「深色」）；
- **query 里的空格被编成 `+`**：ASP.NET Core 的 query 解析不把 `+` 当空格，
  带空格的媒体库名 / 路径 / 搜索词永远匹配不上 —— 改为 `%20`（两种解码解释下都正确）；
- 媒体库卡片的操作按钮在窄屏换行后点不到；
- 隐私政策 / 用户协议里的 `**加粗**` 不再原样显示星号。

## 产物怎么选

| 文件 | ABI | 用途 |
|---|---|---|
| `jellyfin_ohos-v1.1.0-arm64-v8a-unsigned.hap` | arm64-v8a | **真机**推荐，体积最小 |
| `jellyfin_ohos-v1.1.0-universal-unsigned.hap` | arm64-v8a + x86_64 | 真机 + DevEco 模拟器（x86_64 仅为模拟器需要） |

两个产物都是**未签名** HAP：本仓库不含任何签名证书与密钥，未签名包无法直接安装
（安装会报 `code:9568320 error: no signature file`）。请按 `SIGNING.txt` 自行签名
（DevEco Studio 勾选自动签名，或按 `build-profile.json5.template` 手工配置）。

环境要求：HarmonyOS，`compatibleSdkVersion 5.1.0(18)` 及以上，`targetSdkVersion 6.1.0(23)`，
设备类型 `phone`。

## 自带 FFmpeg（软解码）仍然是发布门禁

本版与 v1.0.0 一样把 FFmpeg **编译进应用**：`native/third_party/ffmpeg/source/` 是未经修改的
FFmpeg 7.1 源码（LGPL-2.1-or-later，动态链接、未启用任何 GPL 组件），
`native/app/entry/libs/<abi>/` 是随仓库提交的预编译共享库。安装后**不依赖设备上存在任何 FFmpeg 组件**。

两个产物在发布前都会经过 `scripts/verify_hap_ffmpeg.sh` 校验：`libjellyfin_native.so` 的
`DT_NEEDED` 依赖闭包必须在包内完整，且库的 ELF 架构与 ABI 相符。为什么把它做成门禁：
缺了 FFmpeg 的产物**不会编译失败、也能正常启动**，只有碰到硬解不了的片子才暴露"软解回落不可用"。

## 已知限制

- **媒体库封面不支持从手机本地文件上传**：目前只有「从 URL 设置」（服务器去抓取）。
  本地上传需要系统图片选择器 + 把文件拷进应用沙箱 + 原生按二进制体 POST 三件事一起做，
  在只有模拟器的环境下无法验收，因此没有实现；
- **应用内没有「修改密码」入口**：Jellyfin 的 `POST /Users/{id}/Password` 会注销该账号在
  **其它设备**上的令牌（当前设备保留）。这个动作在真实账号上不便反复验证，因此先不做，
  改密码请在 Web 控制台进行；
- **软解会话只解码视频**：不输出音频、不解析字幕；播放页的轨道面板会明确提示这一点；
- **软解不支持从上次位置续播**：软解回退时会提示「软解暂不支持从上次位置续播，将从头播放」；
- **续播位置受服务端策略影响**：Jellyfin 默认 `MinResumePct=5`、`MinResumeDurationSeconds=300`，
  观看不足 5% 或时长过短时服务端会丢弃续播点 —— 这是服务端行为；
- **模拟器无法硬解 HEVC**：DevEco 模拟器（x86_64）对 HEVC Main10 等编码硬解失败，会自动回退软解；
- **服务端设置页的字段覆盖不是 100%**：转码做了 36/37（未做的是只读的 `EncoderAppPathDisplay`），
  网络做了 23/34（剩下的是 SSDP/UDP 调试、HDHomeRun、多套接字绑定、按请求/按子网发布地址等
  特殊部署项）；理由与清单见 [`docs/settings-user-preferences.md`](../docs/settings-user-preferences.md)；
- **会话凭据存储**：访问令牌当前保存在应用首选项（preferences）中，尚未迁移到
  `@ohos.security.asset`（Asset Store Kit）；该迁移是已记录的待办项。
  令牌不会写入日志、异常文本或截图；
- **兼容性**：面向 Jellyfin 10.8.x 与 10.10.x 实测，更老或更特殊的服务器版本未经实测。
