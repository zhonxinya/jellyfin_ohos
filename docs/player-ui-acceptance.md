# 播放页验收清单（播放 / 渲染 / 美化）

本文件用于**人工快速验收**播放页改动。分三部分：
① 已由设备实测确认的项（附证据）；② 需要人工目视/触控确认的项；
③ 已知限制与临时诊断件。

手动验收约需 **2–3 分钟**：播放任意视频后逐条对照即可。

## 二、需要人工确认（我做不了，自动化手段在此失效）

### 1. 顶部栏锁定按钮
- **操作**：播放页 → 点右上角锁图标
- **预期**：整屏出现「屏幕已锁定」+ 中心圆形解锁按钮
- **为什么需要人工**：`uitest` 三种点击方式（click/doubleClick/longClick）在此按钮上**均无反应**，
  而同一页的 `-10s`、`软解` 等按钮正常。原因未定位（已排除：触达区过小、层级遮挡、点击方式、ButtonType 差异）

### 2. 视频区手势（seek / 音量 / 亮度 / 长按 2× 快进）
- **操作**：播放页 → 手指在视频区横向滑动（seek）、左侧纵向滑动（亮度）、右侧纵向滑动（音量）、按住不动 0.6s（2× 快进）
- **预期**：出现带图标与数值的胶囊状反馈浮层；横向滑动松手后进度跳变
- **为什么需要人工**：`Surface` 型 XComponent 所在区域似乎收不到 `uitest` 注入的合成触摸
  （ArkUI 透明层与原生 `DispatchTouchEvent` 回调**都没有**收到事件）

### 3. 加载态观感
- **操作**：连播多个视频，注意"打开播放器"的瞬间
- **预期**：显示「影片标题 + 类型 + 转圈 + `正在加载 · <播放器状态>`」，而不是空白黑屏
- **为什么需要人工**：该状态通常 <1 秒，抓取周期跟不上

### 4. 整体观感
- 请指出最不满意的 1–2 处（间距/字号/配色/层级），我优先修。

## 三、已知限制与临时诊断件

- **合成触摸限制**：`uitest` 注入的点击/滑动在 ①`AppIconButton`（顶部栏）②视频区（XComponent）
  两处不可靠；按钮区的普通 `Button`/`ChipButton` 正常。**这不代表真实触控失效**。
- **临时诊断件（待清理）**：`AppIconButton` 内的点击探针（写 `ui_tap_probe.txt`）、
  播放页的状态/进度/手势探针（写 `player_state.txt` / `player_progress.txt` / `player_gesture.txt`）。
  这些问题定性后应移除或改为调试开关。
- **服务端会话堆积**：`/Sessions` 曾达 60 条（多为我反复登录/安装的测试痕迹）；
  已在 `EntryAbility.onDestroy` 加"退出时上报停止"的兜底（仅编译验证，`aa force-stop` 不走生命周期回调）。
