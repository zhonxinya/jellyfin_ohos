# 底部导航栏高度一致性（系统导航条区域）

> 面向：验收与后续迭代。记录**问题现象**、**实测数据**、**为什么这么改**与**设备实测证据**。
> 相关代码：`pages/MainShell.ets`（`build()` 根容器 + 底部页签行）、
> `common/WindowFullscreen.ets`（`styleNavigationBarWith` / `exit(win, color)`）。

---

## 一、问题现象

底部页签行看起来"高度不一致"：

- 「媒体库」「设置」页：页签行下面挂着一条**浅色（模拟器上纯白）横带**；
- 「视频」页（沉浸式）：同一位置是应用的深色底，页签行直接顶到屏幕底边。

两处拼在一起，同一个页签行一处"矮一截"、一处"齐到底"。

## 二、实测数据（模拟器 127.0.0.1:5555，1260×2844 px，密度 3.375）

`uitest dumpLayout` + `snapshot_display` 截图逐行取色：

| 页签 | 应用内容区（root 内缩） | 底部页签行 Row | 行高 | 页签行下面那一带 |
|---|---|---|---|---|
| 媒体库 | `[0,132][1260,2750]` | `[0,2561][1260,2750]` | 189px = **56vp** | y=2750..2843 **纯白**（94px = 27.9vp） |
| 设置 | 同上 | 同上 | 同上 | 同上 |
| 视频（沉浸式） | `[0,0][1260,2844]` | `[0,2655][1260,2844]` | 同上 | 无（行本身就是最后一行） |

三条硬事实：

1. **页签行本身的高度三个页签完全一致（56vp）**，图标 74px、文字 40px、间距与内边距也逐像素相同 ——
   所以"高度不一致"不是 `TAB_BAR_HEIGHT` 的问题，而是**页签行下面多出来的那一条**。
2. 那 94px 正好是 `WindowManagerService` 里 `SCBGestureNavBar` 的 bounds（`[0,2750][1260,94]`）。
3. 应用窗口**本来就是整屏**（`WindowRect = [0,0,1260,2844]`），系统导航条底色回读为
   `#00FFFFFF`（全透明）—— 那一条之所以是白的，是因为**应用没有往窗口安全区以外的底部区域画东西**，
   露出的正是系统底（浅色模式下为纯白）。

补充探针（用来排除"改系统栏颜色就行"这条弯路）：`setWindowSystemBarProperties({navigationBarColor})`
调用成功且 `getWindowSystemBarProperties()` 回读为设置值（实测写入 `#FFFF00FF` 也回读到了），
但那条 `SCBGestureNavBar` 仍照原色绘制 —— 该窗口模式下系统导航条的底色不接受应用指定
（`#00FFFFFF` 本来就是"让应用自己画"的语义）。

## 三、改法

1. **外壳根容器把页面底色铺到屏幕底边**（`MainShell.build()`）：
   最外层 `Column` 用底部页签行的底色（`cardBackground`）+ `expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.BOTTOM])`。
   页签行的**内容位置完全不变**（布局不动），只是背景多铺了那 28vp ——
   于是三个页签下"页签行 + 下面那一条"是同一块连续底色。
2. **系统导航条颜色跟着主题走**（`WindowFullscreen.styleNavigationBarWith`）：兜底用。
   在系统导航条**不透明**的机型/窗口模式下，至少让它的颜色与应用一致，不再出现异色横带；
   进入/退出沉浸式（`exit(win, color)`）以及从播放页返回主壳（`onPageShow`）时都会重新染一次。
3. 没有动 `TAB_BAR_HEIGHT`、也没有增加底部内边距：页签行的几何量本来就是对的，
   改它反而会让图标离系统手势条太近或破坏各页统一。

## 四、设备实测（模拟器 127.0.0.1:5555）

| 项 | 结果 |
|---|---|
| 「媒体库」页签行 | `[0,2561][1260,2750]`，行下沿到屏幕底边整条为 `#1C1F24`（无异色横带） |
| 「视频」页签行 | `[0,2655][1260,2844]`，同样无异常色带 |
| 「设置」页签行 | 同「媒体库」 |
| 页签行高度一致性 | 三个页签均为 189px（56vp） |
| 行以下异色横带检测 | 全行宽度 >80% 异色的行数：三页签均为 **0**（手势提示条只有局部像素，不计） |
| 系统手势提示条 | 仍可见，落在深色底上（y≈2806..2826，颜色约 `#383A3E`） |
| 沉浸式来回切换 | 视频 → 媒体库 → 视频 → 设置，`root` 与页签行矩形每次都稳定回到上表数值（可逆） |
| 页签切换 / 抽屉 | 底部三个页签点击均正常切页；抽屉可正常打开（含搜索/继续观看/播放列表/控制台/设置） |
| 编译 | `hvigorw assembleHap`（未签名 debug，双 ABI）`BUILD SUCCESSFUL` |

复跑命令：`python3 /vol3/@appdata/dsh-qddev/dsh-home/_bottomnav-verify.py`（脚本在仓库外）。

## 五、已知限制

- 系统手势提示条的**颜色/显隐**由系统决定（实测它是"跟随底色的浅色小横杠"），应用无法移除；
  本改动只保证它压在应用的连续底色上，不再出现半屏白条。
- 沉浸式下媒体库/设置页的页签行仍在窗口底边（`y=2750`）而不是屏幕底边（`y=2844`）——
  差的那 94px 正是系统导航条区域（沉浸式下被系统栏占用、由系统手势条覆盖）。
  三个页签下"页签行 + 其下区域"的**视觉表现**一致，但页签行本身的屏幕绝对 y 在沉浸式/非沉浸式之间
  会相差一个系统导航条高度，这是窗口内缩（而非页签行高度）导致的，属平台布局行为。
- 只覆盖手机竖屏；折叠屏/平板的系统导航条形态（例如 2in1 的底部任务栏）未在本机验证。
