# 短视频页「全屏 / 设置点不动」修复（设备实测）

## 一、用户报告的现象

> 修复短视频页面无法轻易点击全屏和设置按钮的bug

即：右上角的全屏（展开/收起）与设置（齿轮）两个图标按钮经常点不中。

## 二、先厘清「点不动」到底是哪种

排查时先把现象拆成三个可分别验证的问题，避免修错地方：

| 现象 | 实测结论 |
|---|---|
| 按钮命中范围太小 | ✅ 真问题（见 2.1） |
| 控件隐藏后第一下只唤出、不执行按钮 | 设计如此，但放大了上一条的痛感（见 2.2） |
| 点击被手势层抢走（本页此前踩过） | ❌ **不是**问题，`HitTestMode.Transparent` 的判定一直正常 |

### 2.1 按钮热区只有 32vp，没有做扩展

`TopChrome` 里两个图标按钮原先写死：

```ts
.width(32).height(32).padding(0)
```

按本机密度 3.375 换算只有 **108×108px**，而成人手指的可靠触达尺寸是 **48vp（约 162px）**。

**实测证据（修复前）**：以按钮中心 `(1152,223)` 为原点，水平方向逐点扫描：

| 偏移 | -62 | -54 | -45 | -25 | 0 | 25 | 45 | 54 | 62 |
|---|---|---|---|---|---|---|---|---|---|
| 命中 | ❌ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |

命中边界正好是 **±54px = ±16vp**，即**热区等于视觉尺寸，完全没有扩展**。

作为对照，同一行里带文字的「竖屏」胶囊（约 87×32vp，有 `Text` 撑着）一直都能点中 ——
这说明问题不在"浮层被挡"，而在**纯图标圆钮的可点面积太小**。

### 2.2 控件 4 秒自动隐藏，来不及走到按钮

`kChromeAutoHideMs` 原为 4000ms。控件隐藏后，`onCardTouch` 的设计是
「第一下只把它唤出来，不改播放状态」（这是对的，见 `handleTapUp` 的说明）——

于是用户的实际路径变成：**点一下唤出 → 手指移到右上角 → 按下去**，
只要这一串超过 4 秒，那一下就只会把控件重新唤出，**要点两次才生效**。

**实测证据**：把时序拉开对比（点击「设置」）：

| 唤出后延迟 | 修复前（4s 窗口） | 修复后（6s 窗口） |
|---|---|---|
| 1s | ✅ 跳转 | ✅ 跳转 |
| 3s | ✅ 跳转 | ✅ 跳转 |
| **5s** | ❌ 失败 | **✅ 跳转** |
| 7s | ❌ 失败 | ❌ 失败（超过 6s，符合设计） |

## 三、修复

### 3.1 视觉尺寸与热区分离

新增两个常量，用 `responseRegion` 把热区撑到 48vp：

```ts
const kToolTouchVp: number = 48;          // 最小可靠触达
const kToolTouchSidePadVp: number = 2;    // 左右各多留的量

.responseRegion({
  x: -kToolTouchSidePadVp,               // 左右各溢出 2vp
  y: -(kToolTouchVp - 32) / 2,           // 上下补足到 48vp（溢出 8vp）
  width: 32 + kToolTouchSidePadVp * 2,   // 36vp
  height: kToolTouchVp                   // 48vp
})
```

**为什么左右只扩 2vp 而不是 8vp**：工具行按钮之间有 10vp 的 `space`，
若热区也做满 48vp，相邻两个 32vp 按钮的热区会**重叠 6vp**
（48 − 32 = 16，两边各溢出 8vp > 间距 10vp 的一半），落在重叠带的点击由谁接管
取决于顺序，反而更容易「点了 A 却触发 B」。所以只在**高度方向**扩满
（那个方向没有相邻控件），左右各留 2vp 作为容错。

### 3.2 自动隐藏窗口 4s → 6s

```ts
const kChromeAutoHideMs: number = 6000;
```

6 秒比主流播放器的 3~5 秒略长，换来的是"看到按钮就来得及按"。
控件隐藏后点画面仍只唤出、不改播放状态（`handleTapUp` 逻辑未动），
所以延长窗口**不会**导致误暂停。

## 四、设备验证（Pura70Pro 模拟器，HarmonyOS 6.1.1 API 24）

### 4.1 热区扩展

以按钮中心为原点做垂直扫描（水平已受限，见 3.1）：

| 垂直偏移 | -80 | -70 | -54 | -40 | -27 | -20 | 0 | +20 | +54 | +70 |
|---|---|---|---|---|---|---|---|---|---|---|
| 修复前 | — | — | ✅(边界) | — | — | — | ✅ | — | ✅(边界) | ❌ |
| 修复后 | **✅** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ |

垂直命中范围由 `[-54, +54]` 扩到 **`[-81, +54]`**（理论上界 -81px，与实测 -80 吻合），
即向上多出约 27px 容错 —— 工具行贴顶，用户手指通常略微偏低/偏上，这段余量正好覆盖。

**注意方向不对称**：`responseRegion` 的 `y` 取负值是把热区**向上**扩
（`y = -8vp` 表示热区上边在按钮上边之上 8vp），因此扩展只发生在上方。
这是刻意的——工具行紧贴状态栏下方，向下扩会挤到画面中央区域。

### 4.2 延迟点击（核心场景）

单次 shell 内完成「唤出 → 等待 → 点击 → 判定」，避免 dump 本身的耗时污染计时：

| 场景 | 结果 |
|---|---|
| 唤出后 **1s** 点全屏 | ✅ `root=[0,132][2844,1260]`（横屏全屏） |
| 唤出后 **5s** 点全屏 | ✅ `root=[0,132][2844,1260]`（横屏全屏） |
| 唤出后 **1s** 点设置 | ✅ `pages/settings/ShortVideoSettingsPage` |
| 唤出后 **5s** 点设置 | ✅ `pages/settings/ShortVideoSettingsPage` |
| 唤出后 7s 点设置 | ❌ 仍在外壳（超过 6s 窗口，符合设计） |

### 4.3 回归检查

| 检查项 | 结果 |
|---|---|
| 扩大后的热区内点击（y=180，视觉按钮上方 20px） | ✅ 命中设置 |
| 热区**外**点击（y=130） | ✅ 未误导航；进度 `2:33 → 2:38` 说明**未被暂停** |
| 工具行视觉 | 截图确认**完全未变**（仍是 32vp 图标，「竖屏」胶囊与两个圆钮一行对齐） |
| ArkTS 编译 | `hvigorw assembleHap` → `BUILD SUCCESSFUL` |

## 五、验证脚本要点（可复用）

本页的 UI 自动化有两个容易踩的坑，都会把「没测到」误判成「功能坏了」：

1. **控件 4/6 秒自动隐藏**：`dumpLayout` 本身就要 1~3 秒，多采几次必然撞上隐藏窗口。
   - 稳健做法：`dumpLayout` 先探测 `来自：` 文本是否存在，不存在才单击唤出；
   - 或把「唤出 → 动作 → 判定」压进**同一次 `hdc shell` 调用**（内部分号串联，无往返开销）。
2. **单击是 toggle，且带 380ms 延迟判定**：连点两次 = 显了又隐。
   需要"确保可见"时应先探测再决定是否点击，不要无条件点。

## 六、已知限制

- 热区仍是 **36×48vp**，未达到 44×44vp 的严格舒适区宽度 —— 受限于按钮间距（10vp）。
  若后续要把宽度也做满，需同时把工具行的 `space` 提到 ≥20vp，或把两个按钮并成一个
  分段控件。当前尺寸已通过 4.1/4.2 的实测，先不过度改动。
- 横屏下工具行坐标不同（按钮在屏幕右侧，x≈2594 / 2736），热区逻辑与竖屏共用同一套
  `responseRegion`，无需分支。
