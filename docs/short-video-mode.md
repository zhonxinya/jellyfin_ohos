# 短视频模式（「视频」导航页）

> 面向：验收与后续迭代。记录**已交付行为**、**视觉与交互规格**、**取数/播放策略**、
> **实测证据**与**已知限制**。
> 相关代码：`pages/ShortVideoPage.ets`、`pages/settings/ShortVideoSettingsPage.ets`、
> `common/ShortVideoPrefs.ets`、`pages/MainShell.ets`（页签与外壳顶栏）、
> `components/JellyfinImage.ets`（`fillMode`）。

---

## 一、它是什么

底部导航新增一个**「视频」页**（媒体库 / **视频** / 设置，抽屉里也有入口），承载**短视频模式**：
把用户在设置里勾选的若干**媒体库**当成"短视频源"，随机抽条目、竖屏满屏逐条连播。

为什么单独做一个导航页，而不是塞进媒体库页：「短视频」的心智是**打开就刷**，
与"进库 → 找片子 → 进详情 → 播放"是两条完全不同的动线；混在一起两侧都会变复杂。

## 二、怎么用

1. **设置 → 播放 → 短视频模式**：列出服务器上的媒体库（标注集合类型；对"通常不含视频"的库
   如实提醒），**勾选即保存**（开关类设置不设保存按钮），该行副标题显示「已选 N 个媒体库」；
2. 打开底部**「视频」页**：随机流立刻开始播；**上滑**切下一条，**播完自动下一条**；
3. **单击画面**：暂停 / 继续（中央出现「已暂停」提示）；
4. **双击画面左/右两侧**：快退 / 快进 10 秒（画面中央给出「快进 10 秒」提示，与播放页同一手势）；
5. **右侧操作栏**（竖排四个按钮，图标 + 文字）：**收藏**、**标记已看**、**详情**、**换一批**；
   收藏/已看是**服务端状态**（`UserData`），操作结果用 toast 反馈；
6. **左上角工具行**：`短视频` + 页码 `3/48` + `来自：库A / 库B`；右侧是**方向**
   （跟随系统 / 横屏 / 竖屏，图标 + 文案）与**设置**入口；
7. 底部细进度线 + `已看 / 总时长`；本条播不了时给「去播放页 / 跳过」并倒计时自动跳过。

## 三、视觉规格（本轮美化）

关键改动：**画面铺满整屏，控件做成压在画面上的浮层**（而不是"顶栏 + 工具行 + 一小块画面"）。

| 项 | 做法 | 为什么 |
|---|---|---|
| 外壳顶栏 | 「视频」页签下**不画** `MainShell` 的 `AppTopBar` | 顶栏 56vp 是从画面里直接扣掉的（竖屏手机上接近可见高度的 1/10）；抽屉/搜索在这条动线上用不上，底部页签仍可切走 |
| 顶部工具行 | 浮层 + 顶部渐变 scrim（`120vp + 挖孔内缩`） | 文字在亮画面上也可读，同时不占用画面高度 |
| 环境背景 | 当前封面**铺满 + `scrimHeavy` 压暗**，垫在**视频面之下** | 竖屏是 20:9 窄长屏，横片按"适应"缩放后四周本来是两条纯黑边；垫上同图的暗色放大版后是一整块画面（Plex/Infuse 同款处理） |
| 底部信息 | 类型徽标（品牌色实底 + `onBrand`）+ 系列名 + 标题（≤2 行，20fp）+ 元信息（年 · 评分 · 时长 · 类型，≤1 行）+ 简介（≤2 行） | 短视频的"这一条是什么"必须一眼看清；此前是"标题 + 元信息 + 两个大按钮 + 页码"挤在一行 |
| 右侧操作栏 | 圆形浮层按钮 46vp + 11fp 文字标签，选中态用品牌色实底 | 常用动作收进单手可及的位置；此前「详情/重播」两个大按钮横排在文字旁边 |
| 底部进度 | 3vp 细线 + `mm:ss / mm:ss` | 能看出"还剩多少" |
| 中央状态 | 「正在准备…」转圈 / 「已暂停」大播放图标 / 双击跳转提示 | 切换条目时不再是"黑一下"；暂停与手势有明确反馈 |

## 四、取数策略（为什么这样取）

| 决策 | 原因 |
|---|---|
| 逐库取（`ParentId` 单库） | Jellyfin `/Items` 只接受单个父级；逐库取还能**隔离失败** —— 一个库挂了不影响其它库出内容 |
| `includeItemTypes=Movie,Episode,Video,MusicVideo` | 短视频只关心"能直接播的视频类条目" |
| `SortBy=Random` + 本地 Fisher–Yates | 服务端随机避免"总是同几首"，本地再洗一次避免"总是先放第一个库的内容" |
| 全空时区分"没内容"与"取数失败" | 两者该给的动作不同：**换库** vs **重试** |
| 偏好存 `shortVideoLibraries`（媒体库 **id** 列表） | 名称会随服务端改名/多语言变化，id 才稳定；服务端已删除的库在进设置页时自动剔除 |
| `Fields` 只多要卡片上真的会显示的字段（`OfficialRating,Genres,SeriesName`） | 字段少要 → 分级/类型徽标只能是空白；多要 → 响应变大 |

### 无限流（本轮新增）

- 滑到**距末尾 4 条**时后台预取下一批（`prefetchIfNearEnd`），滑到底不会出现"空白等待"；
- 取到的条目按 id **跨批去重**（`collectBatch(libraryIds, true)`）—— 否则服务端随机
  会把看过的那几条再塞回来，"刷不完"就变成"反复刷同几条"；
- 真的取不到新内容才置 `exhausted`，并在末尾给「这批已经看完了 / 换一批 / 设置」；
- **「换一批」不去重**（`collectBatch(libraryIds, false)`）：它要的是"再来一批新的随机内容"，
  若把已刷过的都排除掉，刷得越多可换的越少；
- 追加是异步的：`feedGeneration` 代次校验保证「换一批」之后不会被上一代的追加结果污染。

## 五、页面行为细节（踩过的坑）

- **空态分两种**：没配过库 → 引导「去设置」；配过但没内容 → 提示换库或先入库内容。
- **从设置页返回必须热更新**：`ShortVideoPage` 是 Tabs 里的普通组件，从设置页返回**不会重建**
  （`aboutToAppear` 不再触发），刚勾完库回到「视频」页会仍是空态。
  做法：`MainShell.videoTabTick` → `@Prop @Watch` 信号，切到该页签时**重读配置**，
  且**只在配置真的变了**（或本来无内容）时才重新取数 —— 否则来回切页签会把正在看的那条随机掉。
- **`getHomeSection('views')` 返回的是 `/Views` 原始响应**（顶层就是 `Items`），
  不是 `{views: {...}}` 包装；用 `JsonUtil.extractItems()` 取（早期版本取错导致"没有可用媒体库"）。
- **工具行/图标**：`sys.symbol.play_rectangle` **不是**有效系统符号（编译期报
  `Unknown resource name`），视频类图标用 `sys.symbol.play_circle`。
- **取数错误不能用"出参字符串"回传**：ArkTS 的 `string` 按值传递，早先版本
  `fetchLibraryBatch(id, outError)` 里写的错误调用方**永远读不到** —— 于是"取数失败"
  被当成"库里没有内容"，该给「重试」的时候给了「去设置」。现在错误记在页面字段 `batchError` 上。
- **单击/双击必须自己判定**：同一块区域上的两个手势，如果同时挂 `onClick` 与双击手势，
  一次双击会顺手触发单击（画面先暂停一下）。做法与播放页一致：单击**延后**
  `kSingleTapDelayMs` 执行，双击到达时取消待执行的单击。
- **浮层按钮不能靠"事件冒泡"过滤**：工具行/操作栏是叠在画面上的浮层，与手势层是**兄弟节点**，
  浮层容器用 `HitTestMode.Transparent`（自身与子节点响应、不阻塞兄弟）才能点得动按钮 ——
  代价是一次点按**同时到达两者**。因此"点按钮"与"点画面"由手势层按**坐标**区分
  （`inChromeZone`：顶部 64 + 挖孔内缩、底部 108、右下操作栏 84×380），
  位置判定与事件顺序无关，比"按钮按下时打标记"可靠。
- **起播看门狗**：`AVPlayer` 有"既不进 playing、也不报 error"的静默状态（转码流起播、弱网）。
  没有看门狗时用户会一直盯着转圈且**永远不会自愈** —— 现在 15 秒没出画面就按"这条播不了"
  处理（转软解 → 提示 + 自动跳过）。
- **自动跳过要一秒一跳**：原先文案是静态的"将在 4 秒后自动跳过"，现在显示剩余秒数。
- **列表被清空时必须显式停播**：状态切到空态/错误态后视频层不再参与构建，但
  AVPlayer/软解会话不会因此停止 —— 不显式收掉的话用户会"看着错误页、听着上一条的声音"。
- **屏幕常亮**：短视频是"长时间只看不摸屏幕"的用法，此前漏了 `setWindowKeepScreenOn`，
  系统息屏时间一到画面就黑掉（观感是"看着看着断了"）；现在播放时开启、离页/切页签还原。
- **封面只画当前这一条**：`ForEach` 会为整批条目建组件，一屏只看得到一条，
  却要为每条拉一张 900px 的图（原生下载 + 解码）。现在只有当前条目画封面，
  一屏一条并发取图的问题随之消失。

## 七、已知限制 / 待验证

- **页内软解**（硬解不支持的条目自动改走 FFmpeg）已实现并设备验证过；
  本页 XComponent **不带 `libraryname`**（软解桥是全进程单例，挂上会与播放页争抢桥状态），
  走 `surfaceId` 路径。
- 短视频页目前**不接 AVSession**（系统媒体控件由播放页负责），多端媒体键行为只在播放页保证。
- **不做无限循环**：末尾给「换一批」，避免"永远刷不完"的假象。
- 环境背景是**同一张封面**的放大压暗版，不是实时画面模糊（无模糊处理的性能开销）；
  后续若要"实时模糊"，需要评估模拟器软渲染下的开销。
- 「这批已经看完了」也可能出现在**追加请求失败**时（弱网）：此时点「换一批」即可重试。
