# 首页顶部推荐位（Hero Banner）

> 面向：验收与后续迭代。记录**行为规格**、**为什么这么改**与**设备实测证据**。
> 相关代码：`components/HeroBanner.ets`（`HeroBanner` + `HeroBannerLoader`）、
> `pages/HomePage.ets`（首页 `HeroBannerLoader()`）。

---

## 一、它是什么

首页最上方的**推荐横幅**：从服务器随机抽一批电影 / 剧集，一屏一条展示横图（Backdrop）+ 标题 + 元信息。

数据来源：`/Users/{userId}/Items?IncludeItemTypes=Movie,Series&Limit=6&SortBy=Random`
（`fields` 里带 `BackdropImageTags`；**没有横图的条目直接跳过** —— 否则滑到那一条是纯色块）。

## 二、行为规格

| 操作 | 行为 |
|---|---|
| **左右滑动** | 切换推荐作品（一屏一条），右下角分页圆点指示当前位置 |
| **点击横幅** | 进入**当前这一条**的详情页 |
| 加载中 | 卡片底色 + 48vp 品牌色转圈（占位高度 = 横幅高度，避免首屏跳动） |
| 取不到内容 | 退化为同高度的纯色占位块（不显示错误文案，首页其它区块继续可用） |

## 三、为什么这么改（设计决策）

1. **移除显眼的播放按钮**。原先横幅右下角有一个 48vp 品牌色实底按钮，文案是「播放」，
   但点击实际是**跳详情页** —— 文案与行为不符；而且它是整块横幅里最抢眼的元素。
   推荐位的任务是"吸引点进去看"，不是在首页直接起播（起播前通常还要看简介/选集/音轨）。
   现在**整块横幅可点**：动作与视觉一致，也没有再误导用户的强按钮。
2. **横向滑动切换**。原来一次只取 1 条（`Limit=1`），永远只有一条推荐 —— 想看点别的只能刷新。
   改成一批（6 条）+ `Swiper` 后，"看推荐"变成可翻的动作；`Limit=6` 是折中：
   够滑几下，又不至于在首屏同时下载太多横图（首页首屏最贵的就是这几张图）。
3. **分页圆点放在右下角**：正好落在原按钮的位置 —— 左侧标题区域不被挤占，
   同时圆点本身就是"这里可以滑"的提示。
4. **不自动轮播**（`autoPlay(false)`）：需求是"可以通过滑动切换"，自动轮播会在用户
   正在读标题时把内容换掉；需要时再开（一行属性）。

## 四、设备实测（模拟器 127.0.0.1:5555）

| 步骤 | 结果 |
|---|---|
| 横幅内「播放」按钮 | **不存在**（`uitest dumpLayout` 里首页 hero 区域无 `播放` 文本节点） |
| 左右滑动 | 第 1 条 `【牛叔】西部世界妖魔横行…` → 第 2 条 `肯尼迪如何得罪半个美国？…` → 第 3 条 `脑洞大开！各种奇葩导航…` |
| 反向滑动 | 回到上一条（第 2 条），顺序与 `Swiper` 索引一致 |
| 点击横幅 | 进入**当前这一条**的详情页（滑到"肯尼迪…"后点击，详情页标题即"肯尼迪…"，证明取的是当前页而不是固定第一条） |
| 回归 | 首页其余区块（我的媒体 / 继续观看）与底部页签不受影响 |
| 编译 | `hvigorw assembleHap`（未签名 debug，双 ABI）`BUILD SUCCESSFUL` |

## 五、已知限制

- 推荐流是**服务端随机**的（`SortBy=Random`），每次进首页/重载都不同 —— 这是"推荐"的预期，
  但也意味着**没有个性化**（不基于观看历史）；后续若要"按口味推荐"，需要走
  Jellyfin 的 `/Items/{id}/Similar` 或用户播放历史做客户端加权。
- 每次重载会重新随机（`HeroBannerLoader.aboutToAppear` 只加载一次；切页签回来不会重建，
  因此同一次使用内顺序稳定）。
- 只对**有横图（Backdrop）**的条目做推荐；纯竖图条目在这个位置不出现（竖图裁成横图会毁构图）。
